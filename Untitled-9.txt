```md
# Code Standards — Always On
## Activation
- Type: Always On
## Rules
### TypeScript
- Strict mode immer aktiviert
- Kein `any` — verwende `unknown` + Type Guards wenn nötig
- Alle Funktionsparameter und Rückgabewerte typisiert
- Interfaces bevorzugt über Type Aliases für Objekte
- Enums vermeiden — verwende Union Types: `type Status = 'active' | 'paused'`
### Naming
- Komponenten: PascalCase (`CampaignHub.tsx`)
- Hooks: camelCase mit `use` Prefix (`useCampaignStore.ts`)
- Utilities: camelCase (`formatDate.ts`)
- Types: PascalCase (`Campaign`, `AgentTask`)
- Konstanten: UPPER_SNAKE_CASE (`API_BASE_URL`)
- CSS Klassen: Tailwind Utilities, keine custom CSS
### Dateistruktur
- Max 200 Zeilen pro Datei — aufteilen wenn größer
- Ein Export pro Datei bevorzugt
- Index-Dateien nur für Module, nicht für einzelne Komponenten
- Relative Imports innerhalb eines Moduls, Alias-Imports (`@/`) zwischen Modulen
### Error Handling
- Jeder API Call hat try/catch
- Jede async Funktion hat Error Handling
- Errors werden geloggt UND dem User angezeigt
- Keine stummen catch-Blöcke
### Imports
- React Imports zuerst
- Third-party Imports zweiter
- Interne Imports dritter (alphabetisch)
- Typen-Imports mit `import type`
```

```md
# Architecture Rules — Always On
## Activation
- Type: Always On
## Rules
### Frontend Architecture
- Jedes Modul lebt in `/src/modules/[ModuleName]/`
- Module importieren NIEMALS direkt voneinander — nur über shared/
- Shared Components in `/src/shared/components/`
- Shared Hooks in `/src/shared/hooks/`

- Services sind stateless — kein globaler mutable State
- Firestore ist die einzige Datenquelle der Wahrheit

- Agent-Execution über AgentRuntime Service
### API Design
- REST mit /api/v1/ Prefix
- Konsistentes Response Format: { success, data, meta } oder { success, error }
- HTTP Status Codes korrekt verwenden
- Pagination für alle Listen-Endpoints
### Infrastructure
- Frontend: Firebase Hosting
- Backend: Cloud Run (europe-west1)
- Database: Firestore
- Storage: Cloud Storage
- AI: Vertex AI (Gemini 2.0 Pro, Imagen 3)
- Events: Pub/Sub
- Secrets: Secret Manager
- GCP Project: alphate-enterprise-g5
- Firebase Project: online-marketing-manager
```

```md
# React Patterns — Frontend
## Activation
- Type: Glob
- Pattern: src/**/*.tsx, src/**/*.ts
## Rules
### Component Pattern
- Functional Components mit FC Type
- Hooks Reihenfolge: useState → useRef → Custom Hooks → useEffect
- Derived State: Berechne in der Render-Phase, kein useEffect
- Event Handler als const innerhalb der Komponente
### State Management
- Server State: useQuery / useMutation (TanStack React Query)
- Global UI State: Zustand Stores (useUIStore, useNotificationStore)
- Module State: Eigener Zustand Store pro Modul
- Form State: React Hook Form oder controlled Components
- URL State: useSearchParams / useParams
### Performance
- React.lazy() für alle Module (Route-Level Code Splitting)
- useMemo für teure Berechnungen (Array.filter, .map, .sort)
- useCallback nur wenn an memoized Children weitergegeben
- React.memo nur für Komponenten die häufig re-rendern ohne Prop-Änderung
- Virtualisierung mit react-window für Listen > 100 Items
### Styling
- Tailwind CSS v4 Utilities — keine CSS Dateien
- cn() Helper (clsx + tailwind-merge) für bedingte Klassen
- Design Tokens: Farben, Spacing, Border Radius aus Tailwind Config
- Responsive: Mobile-Tolerant, Desktop-First
- Dark Mode: Standard — alle Farben für Dark Mode optimiert
### Animation
- Framer Motion für: Page Transitions, Modal Open/Close, List Items
- Tailwind transition für: Hover, Focus, Active States
- IMMER: reducedMotion Check via useMediaQuery('(prefers-reduced-motion: reduce)')
```

```md
# API Design Rules — Backend
## Activation
- Type: Glob
- Pattern: backend/src/**/*.ts
## Rules
### Endpoint Structure
- GET /api/v1/{resource} → Liste (mit Pagination)
- GET /api/v1/{resource}/:id → Einzelnes Item
- POST /api/v1/{resource} → Erstellen
- PUT /api/v1/{resource}/:id → Vollständiges Update
- PATCH /api/v1/{resource}/:id → Teilweises Update
- DELETE /api/v1/{resource}/:id → Löschen
- POST /api/v1/{resource}/:id/{action} → Spezial-Aktion (execute, publish)
### Response Format
Erfolg:
{ "success": true, "data": { ... }, "meta": { "timestamp": "ISO", "requestId": "uuid" } }
Fehler:
{ "success": false, "error": { "code": "ERROR_CODE", "message": "Human readable", "details": {} } }
Liste:
{ "success": true, "data": [...], "meta": { "pagination": { "page": 1, "limit": 20, "total": 100, "totalPages": 5 } } }
### Validation
- Zod Schema für jeden Request Body
- Query Parameter validieren (page, limit, sort, filter)
- Path Parameter validieren (UUID Format, etc.)
### Error Handling
- Hono onError Handler fängt alles ab
- Custom Error Klassen: NotFoundError, ValidationError, AuthError, RateLimitError
- Unerwartete Errors: 500 mit generischer Nachricht (Details nur in Logs)
```

```md
# Firestore Patterns — Backend
## Activation
- Type: Glob
- Pattern: backend/src/**/*.ts
## Rules
- Batch Writes für mehrere Dokumente (max 500 per Batch)
- Transactions für atomare Read-then-Write Operationen
- Indexes für häufige Queries in firestore.indexes.json definieren
- Subcollections für 1:N Beziehungen (campaign → outputs, agent → history)
- Denormalisierung ist OK wenn es Reads reduziert
- Timestamps: Firestore Timestamp Typ, nie JavaScript Date direkt
- Document IDs: Auto-generated oder semantisch sinnvoll (z.B. Datum für analytics)
- Pagination: startAfter + limit (Cursor-basiert, NICHT offset)
- Real-Time Listeners nur im Frontend — Backend nutzt reguläre Reads
```

# New API Endpoint Workflow
## Description
Erstellt einen neuen Backend API Endpoint auf Cloud Run.
## Parameters
- RESOURCE: Resource Name (z.B. campaigns, content)
- METHOD: HTTP Method (GET, POST, PUT, DELETE)
- PATH: Endpoint Path (z.B. /api/v1/campaigns/:id/execute)
- DESCRIPTION: Was der Endpoint tut
## Steps
### 1. Planung
- Lies das Backend-Entwicklerhandbuch
- Definiere Request/Response Format
- Definiere Zod Validation Schema
- Identifiziere benötigte Services
### 2. Zod Schema erstellen
- Öffne oder erstelle backend/src/routes/{RESOURCE}.ts
- Definiere Request Body Schema mit Zod
- Definiere Response Type
### 3. Route Handler implementieren
````ts
// Pattern:
router.{METHOD}('{PATH}', validate(schema), async (c) => {
  const body = c.get('validatedBody')
  const user = c.get('user')
  const result = await service.method(body, user)
  return c.json({ success: true, data: result, meta: { timestamp: new Date().toISOString() } })
})
````
### 4. Service Logic implementieren
- Implementiere die Business Logic im entsprechenden Service
- Verwende Firestore Transactions wenn nötig
- Emittiere Events über Pub/Sub wenn relevant
- Logge wichtige Aktionen
### 5. Error Handling
- Verwende Custom Error Klassen
- Alle Firestore/Vertex AI Calls in try/catch
- Sinnvolle Error Messages für den User
### 6. Testen
- Teste mit curl oder dem Browser Subagent
- Teste Happy Path
- Teste Validation Errors (fehlende Felder, falsche Typen)
- Teste Auth Errors (kein Token, ungültiger Token)
- Teste Not Found Cases
- Prüfe Firestore nach dem Call
### 7. Deploy
- Nutze Workflow: /deploy

# Deploy Workflow
## Description
Deployment der Anwendung zu Firebase Hosting und/oder Cloud Run.
## Parameters
- TARGET: "frontend" | "backend" | "both" | "rules"
## Steps
### 1. Pre-Deploy Checks
- `npm run build` — muss fehlerfrei durchlaufen
- `npx tsc --noEmit` — keine TypeScript Errors
- `npm run lint` — keine Linting Errors
- Prüfe .env Variablen für Production
### 2. Frontend Deploy (wenn TARGET = frontend oder both)
````bash
cd frontend  # oder Root wenn Monorepo
npm run build
firebase deploy --only hosting --project online-marketing-manager
````
- Verifiziere: https://online-marketing-manager.web.app
- Prüfe Console auf Errors
- Teste kritische Flows
### 3. Backend Deploy (wenn TARGET = backend oder both)
````bash
cd backend
gcloud builds submit --tag gcr.io/alphate-enterprise-g5/agenticum-g5-backend --project alphate-enterprise-g5
gcloud run deploy agenticum-g5-backend \\
  --image gcr.io/alphate-enterprise-g5/agenticum-g5-backend \\
  --region europe-west1 \\
  --platform managed \\
  --allow-unauthenticated \\
  --project alphate-enterprise-g5
````
- Verifiziere: GET /api/v1/health
- Prüfe Cloud Run Logs: `gcloud logging read "resource.type=cloud_run_revision" --limit=20 --project alphate-enterprise-g5`
### 4. Firestore Rules Deploy (wenn TARGET = rules)
````bash
firebase deploy --only firestore:rules --project online-marketing-manager
````

- Öffne Production URL im Browser Subagent
- Navigiere durch alle Hauptmodule
- Prüfe Network Tab: keine 404s, keine 500s
- Prüfe Console: keine Errors
- Teste einen End-to-End Flow (z.B. Content generieren)

Falls Fehler auftreten:
- Frontend: `firebase hosting:channel:deploy rollback` oder vorherige Version
- Backend: `gcloud run services update-traffic agenticum-g5-backend --to-revisions=PREVIOUS_REVISION=100 --region europe-west1`

````markdown
# AGENTICUM G5 — OS UX & INTERACTION DESIGN HANDBUCH
---
## 1. DESIGN PHILOSOPHY
AGENTICUM G5 ist kein Dashboard — es ist ein Operating System. Jede Design-Entscheidung
folgt diesen Prinzipien:
1. **Power User First:** Optimiert für Keyboard-Power-User, erreichbar für Mouse-User
2. **Information Density:** Maximale Information bei minimaler Cognitive Load
3. **Zero Friction:** Jede Aktion erreichbar in ≤3 Klicks oder ≤1 Keyboard Shortcut
4. **Real-Time:** Alles was sich ändert, aktualisiert sich sofort — kein Reload
5. **Context Preservation:** Navigation verliert niemals den aktuellen State
6. **Progressive Disclosure:** Einfach beim ersten Blick, tief beim Erkunden
````

````markdown
# AGENTICUM G5 — FIRESTORE SECURITY RULES
## DATEI: firestore.rules
````
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Helper Functions
    function isAuthenticated() {
      return request.auth != null;
    }
    function isOwner(userId) {
      return request.auth.uid == userId;
    }
    function hasRole(role) {
      return request.auth.token.role == role;
    }
    function isAdmin() {
      return hasRole('admin');
    }
    function isValidTimestamp(field) {
      return request.resource.data[field] is timestamp;
    }
    // Campaigns
    match /campaigns/{campaignId} {
      allow read: if isAuthenticated();
      allow create: if isAuthenticated()
        && request.resource.data.keys().hasAll(['name', 'status', 'channels', 'createdAt'])
        && request.resource.data.status == 'draft';
      allow update: if isAuthenticated();
      allow delete: if isAdmin();
      match /outputs/{outputId} {
        allow read: if isAuthenticated();
        allow write: if isAuthenticated();
      }
    }
    // Content
    match /content/{contentId} {
      allow read: if isAuthenticated();
      allow create: if isAuthenticated()
        && request.resource.data.keys().hasAll(['title', 'type', 'status', 'createdAt']);
      allow update: if isAuthenticated();
      allow delete: if isAdmin();
    }
    // Agents
    match /agents/{agentId} {
      allow read: if isAuthenticated();
      allow update: if isAuthenticated(); // Config changes
      allow create, delete: if isAdmin();
      match /history/{taskId} {
        allow read: if isAuthenticated();
        allow create: if isAuthenticated(); // Runtime creates entries
      }
    }
    // Workflows
    match /workflows/{workflowId} {
      allow read: if isAuthenticated();
      allow create, update: if isAuthenticated();
      allow delete: if isAdmin();
      match /runs/{runId} {
        allow read: if isAuthenticated();
        allow create, update: if isAuthenticated();
      }
    }
    // Assets
    match /assets/{assetId} {
      allow read: if isAuthenticated();
      allow create: if isAuthenticated();
      allow update: if isAuthenticated();
      allow delete: if isAuthenticated();
    }
    // Senate
    match /senate/{caseId} {
      allow read: if isAuthenticated();
      allow create: if isAuthenticated();
      allow update: if isAuthenticated()
        && (request.resource.data.diff(resource.data).affectedKeys()
            .hasOnly(['status', 'decision', 'updatedAt']));
    }
    // Knowledge Base
    match /knowledge/{docId} {
      allow read: if isAuthenticated();
      allow create: if isAuthenticated();
      allow update: if isAuthenticated();
      allow delete: if isAdmin();
      match /chunks/{chunkId} {
        allow read: if isAuthenticated();
        allow write: if isAuthenticated();
      }
    }
    // Notifications
    match /notifications/{notifId} {
      allow read: if isAuthenticated();
      allow create: if isAuthenticated();
      allow update: if isAuthenticated()
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['read']);
    }
    // Analytics (Read-only für Frontend, Write durch Backend/Functions)
    match /analytics/{dateId} {
      allow read: if isAuthenticated();
      allow write: if false; // Nur Backend/Cloud Functions
    }
    // Config
    match /config/{configId} {
      allow read: if isAuthenticated();
      allow write: if isAdmin();
    }
    // Audit Log (Read-only)
    match /audit/{eventId} {
      allow read: if isAuthenticated();
      allow write: if false; // Nur Backend
    }
    // Default: Deny All
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
